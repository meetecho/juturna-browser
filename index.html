What's actually running

Four demos, four different node types, all through the same facade: Juturna.create(), pipe.input().feed(), pipe.output().on('message'). Real models (Whisper, OPUS-MT, a portrait segmenter, DeepFilterNet3), each its own Pyodide Worker so a CPU-heavy node never stalls the others.

Run it yourself

Checkouts of juturna (3.0.0 or later) and of juturna-nodes, and Python 3.12, are the only requirements beyond Chrome 137+.

  1. Vendor the third-party files each demo declares (models, onnxruntime-web, transformers.js): 
    python3 build/vendor.py examples/live-translation/plugins examples/video-blur/plugins examples/noise-suppression/plugins examples/plugins
    The Kroko demo's model is different: it is compiled into its WASM runtime, not fetched by vendor.py - see its node's README for the (one-time) build step.
  2. Build the wheel and the plugins bundle. --plugins repeats, so one bundle can serve every demo: 
    python3 build/build.py --juturna ~/path/to/juturna --nodes ~/path/to/juturna_nodes \
    --plugins examples/live-translation/plugins \
    --plugins examples/video-blur/plugins \
    --plugins examples/noise-suppression/plugins \
    --plugins examples/plugins
  3. Serve it (the isolation headers SharedArrayBuffer needs are only in this server, not a generic static host): 
    python3 serve.py 8765
    Then open localhost:8765 - this same page, served locally.
